# cli-srv

Два приложения на C++ для Linux: CLI-клиент и многопоточный сервер, обмен строками по IPC.

## Задача

1. **Клиент (`app1_cli`)** — читает строку до перевода строки, передаёт её серверу по IPC, печатает ответ.
2. **Сервер (`app2_server`)** — принимает строку, переворачивает её, возвращает клиенту; в лог пишет локальное время, исходный текст и длительность обработки.
3. **`run.sh`** — собирает и запускает оба процесса; **`stop`** завершает сервер (из режима **`start`**) и все процессы **`build/app1_cli/app1_cli`** этой копии репозитория. В режиме **`run`** после выхода из CLI или **Ctrl+C** снимается только **сервер** (клиент уже завершился сам или получил сигнал с терминала).

**Общие требования:** CMake **3.25+**, **GCC**, целевая ОС — **Ubuntu 22.04**. Сборка — из корня репозитория.

## IPC

**Unix domain socket** (`AF_UNIX`, потоковый), путь по умолчанию `/tmp/ipc.sock`. Для пары процессов на одной машине это даёт запрос–ответ без сетевого стека и с тем же API, что у TCP-сокетов.

Переопределение: `SOCKET_PATH` для `run.sh` или `./app1_cli <путь>` / `./app2_server <путь_сокета> [путь_лог]`.

## Сборка

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

либо `./run.sh build`. Бинарники: `build/app1_cli/app1_cli`, `build/app2_server/app2_server`.

## Запуск

- Интерактивно: `./run.sh` или `./run.sh run` — сервер в фоне, CLI в переднем плане. После **EOF (Ctrl+D)** или выхода из клиента срабатывает `trap` в скрипте и **процесс сервера завершается**; клиент к этому моменту уже завершился сам. **Ctrl+C** тоже вешает тот же `trap` — сервер будет убран явно.
- Только сервер: `./run.sh start`, клиенты вручную — **`./run.sh stop`** гасит **сервер** (PID в `.runtime/app2_server.pid`) и шлёт **`pkill -f`** по пути к **`app1_cli`** из этого репозитория, чтобы не оставались висящие CLI после обрыва сервера.

**Несколько клиентов:** после `./run.sh start` можно параллельно запустить несколько `./app1_cli` с тем же путём сокета. Главный поток только **`accept`**; очередь `listen(..., 5)`; на каждое соединение — **`std::thread`**: чтение, переворот, запись в лог (`std::mutex`), ответ, `close` клиентского fd.

Через `run.sh` лог: `<корень_репозитория>/server.log`. При ручном запуске сервера без второго аргумента — `server.log` в текущем каталоге.
