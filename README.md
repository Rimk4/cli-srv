# cli-srv

Два процесса на C++ под Linux: интерактивный CLI-клиент и многопоточный сервер, обменивающиеся строками через IPC. Сервер переворачивает строку, пишет событие в лог и возвращает результат.

## Требования

- Linux с **Unix domain sockets** (`AF_UNIX`; типичный десктоп или встраиваемый дистрибутив на glibc/musl)
- GCC или Clang с поддержкой **C++17**
- CMake **3.25+**

## Структура

| Каталог / файл | Назначение |
|----------------|------------|
| `app1_cli/` | CLI: ввод строки, отправка на сервер, вывод ответа (цикл до EOF / Ctrl+D) |
| `app2_server/` | Сервер: `accept` в главном потоке, обработка в `std::thread`, лог в файл |
| `run.sh` | Сборка и запуск пары, либо `start` / `stop` для фонового сервера |
| `CMakeLists.txt` | Корневая сборка обоих приложений |

## IPC

Используется **Unix domain socket** (`AF_UNIX`, `SOCK_STREAM`), путь по умолчанию: `/tmp/ipc.sock`.

**Почему так:** один сокет на файловой системе удобен для пары «клиент–сервис» на одной машине, даёт потоковую семантику запрос–ответ без сетевого стека, хорошо переносим на встраиваемые системы с тем же API, что и сетевые сокеты.

Переопределение пути сокета: переменная окружения `SOCKET_PATH` (для `run.sh`) или аргумент `./app1_cli <путь_к_сокету>`.

Сервер: `./app2_server [путь_к_сокету] [путь_к_логу]` — по умолчанию сокет `/tmp/ipc.sock`, лог `server.log` (см. ниже).

## Сборка

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j"$(nproc)"
```

Или:

```bash
./run.sh build
```

Артефакты: `build/app1_cli/app1_cli`, `build/app2_server/app2_server`.

## Запуск

**Интерактивно** (сервер в фоне, CLI в переднем плане; после выхода из CLI сервер завершается):

```bash
./run.sh
# или
./run.sh run
```

**Сервер отдельно** (PID в `.runtime/app2_server.pid`):

```bash
./run.sh start
./run.sh stop
```

**Лог сервера**

- Через **`./run.sh`** (включая `run`, `start`): путь к логу задаётся скриптом как **`$ROOT/server.log`**, где `$ROOT` — каталог репозитория (файл с `run.sh`), независимо от того, из какого каталога вы вызвали скрипт.
- При **ручном** запуске бинарника без второго аргумента: по умолчанию используется относительный путь **`server.log`** — файл создаётся в **текущем рабочем каталоге** процесса сервера. Второй аргумент командной строки задаёт произвольный путь к логу.

В строке лога: локальное время, исходная строка, время обработки (микросекунды).

## Кратко о потоках (app2)

Главный поток слушает сокет и принимает соединения; для каждого клиента создаётся поток, в нём чтение строки, переворот, запись в лог (с `std::mutex`) и отправка ответа.
